# Зелёный магазин на Bootstrap

Контрольная работа №2 по дисциплине «Фронтенд и бэкенд разработка». Тема: «CSS-фреймворки: разработка интерфейса на Bootstrap или альтернативном CSS-фреймворке».

Отдельная версия магазина многоразовых вещей на Bootstrap 5.3.8. В каталоге шесть товаров, связанные описания, таблица сравнения и учебная форма заявки. Тема, изображения и сведения о товарах продолжают предметную область КР №1; сетка и компоненты реализованы средствами Bootstrap.

## Подключение Bootstrap

Bootstrap 5.3.8 подключён локально из `vendor/bootstrap/`. Используется готовый compiled-дистрибутив:

```html
<link rel="stylesheet" href="vendor/bootstrap/css/bootstrap.min.css">
<link rel="stylesheet" href="css/custom.css">
<script src="vendor/bootstrap/js/bootstrap.bundle.min.js" defer></script>
<script src="js/main.js" defer></script>
```

`custom.css` подключён после Bootstrap и содержит фирменную палитру, первый экран и отдельные уточнения компонентов. Основная сетка, формы, меню, окна и вкладки используют Bootstrap. Файл из КР №1 не подключается.

JS Bundle обеспечивает раскрытие меню, модальные окна, Accordion, Tabs и Carousel; он также включает Popper. Собственный `main.js` создаёт экземпляр карусели, выбирает товар из адреса и показывает учебное подтверждение формы. Лицензия Bootstrap сохранена в `vendor/bootstrap/LICENSE`.

- Локальное подключение Bootstrap без CDN с сохранением лицензии.
- Дополнительная страница контактов, связанная с заявкой на консультацию.
- Каталог из шести товаров с категориями, SVG-иллюстрациями, ценами, скидкой и ссылками на соответствующие описания.
- Отдельная таблица сравнения популярных товаров вместе с таблицами характеристик.
- Вкладки «Характеристики», «Уход», «Получение» для каждого товара. Идентификаторы вкладок и панелей уникальны.
- Карусель трёх идей с ручным управлением: кнопки, индикаторы, стрелки клавиатуры и свайпы. Автоматическое пролистывание выключено; каждый слайд связан с описанием и заявкой своего товара.
- Передача выбранного товара через `order.html?product=bottle`. Скрипт выбирает только существующий вариант списка; неизвестное значение игнорируется.
- Дополнительные поля количества и получения. Подтверждение показывает выбранный товар, количество и способ получения, сохраняя поля для правки.
- Фирменный первый экран и зелёная палитра через `custom.css`, логичные имена собственных классов.
- Ссылка пропуска навигации, клавиатурный фокус, связанные подсказки, `scope` в таблицах и уменьшение движения по предпочтению пользователя.
- Перестроение меню, каталога, формы и подвала по ширине. На коротких страницах основное содержимое занимает свободное место и удерживает подвал снизу.

Accordion уже приведён в базовом примере практической №10. Самостоятельное расширение демонстрируют его содержательная настройка, дополнительные Tabs, страницы, локальные зависимости и связанный сценарий заявки.

## Сценарий заявки

1. Нажмите «Выбрать» у товара в каталоге или «Выбрать для заявки» в описании.
2. Откроется `order.html` с допустимым значением `product` в адресе. Этот товар будет выбран в списке.
3. Заполните имя, email и десять цифр телефона после видимого +7, например `9001234567`.
4. Выберите количество, получение и обязательное согласие.
5. Нажмите «Проверить заявку». Сначала браузер проверит HTML-ограничения, затем обработчик отменит стандартную отправку и откроет Bootstrap Modal.

Префикс +7 — отдельный текстовый элемент, в самом поле только десять цифр. `input-group` не добавляет префикс к значению автоматически. Кнопка очистки возвращает исходные HTML-значения: пустые контакты и выбор товара, количество 1, самовывоз. Предвыбор из адреса не меняет эти значения сброса.

## Границы учебного макета

Работают переходы, предвыбор товара, мобильное меню, Accordion, Tabs, проверка полей, сброс и диалоги.

Фильтр стоимости — макет: кнопка применения отключена и это пояснено рядом. Корзина, оплата, пересчёт суммы, база данных и серверная отправка отсутствуют. Контакты и условия демонстрационные; домен `.example` не принимает реальные письма.

Форма не использует `fetch`, localStorage или другую собственную запись данных. Подтверждение означает только прохождение браузерной проверки. Браузер может использовать своё автозаполнение; это отдельный механизм. В настоящем приложении нужна повторная проверка на сервере.

## Как проверить

- Открыть все пять страниц и каждый переход «Подробнее» и «Выбрать».
- Проверить предвыбор всех шести товаров и консультации; неизвестный `product` не должен выбирать товар.
- На узком экране открыть и закрыть меню.
- Раскрыть FAQ, переключить все три вкладки товара и открыть окно условий.
- В карусели проверить «Назад», «Дальше», все три индикатора, стрелки клавиатуры и свайп на сенсорном экране. После третьего слайда следующий возвращает к первому.
- Пройти элементы клавишей Tab; проверить закрытие окон крестиком, кнопкой и Escape.
- Проверить пустую форму, неправильный email, короткий/нецифровой телефон, количество вне 1–10 и отсутствие согласия.
- Заполнить форму корректно: появится подтверждение с выбранным товаром и способом получения. Сетевого запроса с данными быть не должно.
- Проверить очистку формы, работу через `file://`, отсутствие запросов к CDN и загрузку локальных зависимостей.
- Проверить ширины 360–390, 768, 1024 и 1440 px, прокрутку таблицы и подвал при уменьшении масштаба.
- Проверить опубликованные страницы и пути ресурсов после завершения GitHub Pages.

GitHub Pages публикует ветку `main`. Файл `.nojekyll` обеспечивает публикацию статических файлов без обработки Jekyll.

## Выполненная проверка

В Chrome проверены все пять страниц на ширинах 360, 390, 768, 1024, 1440 и 5760 CSS-пикселей: 30 сочетаний страницы и размера окна. Горизонтального переполнения страницы и подъёма подвала на короткой странице не обнаружено.

Проверены ссылки и якоря, уникальность id, связи подписей и полей, изображения, пять мобильных меню, все 18 вкладок, предвыбор шести товаров и консультации, неизвестный параметр, раскрытие FAQ и закрытие окон. Проверены ошибочные и корректные значения формы, сохранение полей после подтверждения и сброс.

При проверке не было запросов к CDN, POST-запросов формы, ошибок загрузки ресурсов и ошибок JavaScript. Дополнительно проверено открытие через `file://`.

Карусель отдельно проверена на ширинах 360, 390, 768 и 1440 px: кнопки, все индикаторы, переход с последнего слайда к первому, клавиатура, первый свайп, режим уменьшения движения и отсутствие автоматического листания. На каждом размере окна высота трёх слайдов одинаковая.
